# UI Design System V1 — Light Minimal Tech

本版本已完成 12 项全局规范确认，包含视觉、组件、布局、数据可视化、动效和响应式规则。

## 1. Skill 使用原则

本 Skill 是项目级全局 UI 规范。开发新页面、重构页面、创建组件或调整视觉样式时，必须优先遵循本规范。

- 先检查项目现有技术栈、组件库、设计令牌和页面结构，再实施修改。
- 优先复用 `@/components/ui` 中已有的 shadcn/ui 组件。
- 使用 Tailwind CSS；条件类名使用项目现有的 `cn()` 工具。
- 不重复造轮子，不为了局部页面另建一套视觉体系。
- 所有颜色统一通过 `globals.css` 中的 CSS 设计令牌管理；业务组件禁止硬编码颜色值。
- 可以基于真实业务需求扩展语义令牌，但不得随意增加品牌强调色。
- 保持可访问性：语义化 HTML、键盘可操作、清晰焦点态、足够的颜色对比度。
- 不擅自改动与当前任务无关的业务逻辑、路由、数据结构或页面功能。

## 2. 总体设计方向

**风格：Light Minimal Tech（明亮极简科技风）**

- 默认使用 Light Mode。
- 整体明亮、克制、清晰、现代，符合现代 SaaS 产品气质。
- 通过留白、排版、浅色边框和轻微阴影建立层级。
- 信息密度为适中型，兼顾业务后台的操作效率与阅读舒适度。
- 避免厚重、繁复、装饰性强的视觉效果。

### 明确禁止

- 不使用紫色、蓝紫色或紫色渐变。
- 禁止装饰性渐变。图表可使用具有明确数据含义且配有图例的功能性渐变。
- 不使用玻璃拟态或过度发光效果。
- 不使用胶囊形按钮或过度圆润的组件。
- 不使用装饰性 Emoji 作为功能图标。
- 不使用卡片左边缘彩色装饰线。
- 不要把所有内容都包进卡片，避免卡片套卡片。
- 默认不要使用三列功能卡片网格作为通用页面布局。
- 不添加没有实际交互价值的动画。
- 不为了视觉丰富而随机使用多种品牌色。

## 3. 颜色系统

所有颜色必须通过 `globals.css` 的 CSS variables / design tokens 管理，组件中使用语义令牌，不直接写死颜色。

### 品牌与语义色

| 用途 | 色值 |
|---|---|
| 默认主强调色 / Primary | `#2563EB` |
| 辅助强调色 / Cyan | `#06B6D4` |
| Success | `#16A34A` |
| Warning | `#F59E0B` |
| Destructive / Error | `#DC2626` |

### 品牌色优先级

- 先检查项目现有主题、品牌配置和语义令牌。
- 没有既定品牌色时，UI 主色使用科技蓝 `#2563EB`。
- 已有蓝色系品牌色且相关前景和背景组合满足可访问性要求时，将该品牌色映射到统一主题令牌。
- 已有其他品牌色时，保留品牌资产，UI 默认仍采用科技蓝。应用默认色如需变更既有品牌主题，须先确认。
- 不得未经确认修改既有品牌主题。紫色和蓝紫色禁止作为 UI 配色。

### 基础色

| 用途 | 色值 |
|---|---|
| 白色 | `#FFFFFF` |
| 浅灰背景 | `#F3F4F6` |
| 次级文字 | `#626B78`（在浅灰背景 `#F3F4F6` 上约为 4.90∶1） |
| 深色文字 | `#171717` |

- 页面默认采用浅色背景。
- 主按钮、选中状态和主要交互使用主题主色。
- 辅助青色只用于有明确数据或交互意义的辅助场景。
- 状态颜色必须按语义使用。
- 指标变化默认采用红升绿降：上升/增长使用红色 `#DC2626`，下降/回落使用绿色 `#16A34A`，需关注使用橙色 `#F59E0B`。普通交互与系统状态仍按语义着色（Success 绿、Warning 橙、Destructive/Error 红）。
- 所有组件颜色应使用项目中的语义化 CSS 变量，例如 `--primary`、`--border`、`--input`、`--ring`、`--muted`、`--destructive` 等。若项目令牌命名不同，先映射现有体系，不要另建平行色彩系统。

## 4. 字体与排版

### 字体栈

优先使用项目已有字体资源，避免不必要的外部网络依赖。

```css
font-family:
  "Inter",
  "Noto Sans SC",
  "PingFang SC",
  "Microsoft YaHei",
  sans-serif;
```

- 西文及数字优先 Inter。
- 中文优先 Noto Sans SC。
- 系统回退为 PingFang SC、Microsoft YaHei、sans-serif。

### 字重

| 场景 | 字重 |
|---|---:|
| 正文 | 400 |
| 表单标签 / 次级标题 | 500 |
| 区块标题 / 页面主标题 | 600 |
| 强调 | 700（少量使用） |

### 字号建议

| 场景 | 字号 |
|---|---:|
| 页面主标题 | 30px |
| 区块标题 | 24px |
| 卡片标题 | 20px（图表标题使用 16px） |
| 重要正文 | 16px |
| 常规内容 | 14px |
| 辅助信息 | 12px |

### 字号优先级

页面主标题 ＞ 区块标题 ＞ 内容容器标题 ＞ 正文与表格内容 ＞ 辅助信息。

- 同一视口最多使用四种字号，优先控制在三种。
- 各组件规定的字号是默认值。同一视口中字号超过四种时，按上述层级复用字号，保持文字层级清晰。下文的组件字号默认值均受此上限约束。
- 最小字号原则上不低于 12px。
- 文字层级应清晰，不通过大量粗体制造层级。

## 5. 间距与圆角

### 间距

使用 Tailwind 默认 4px 间距体系。

| 场景 | 间距 |
|---|---:|
| 页面左右边距 | 24px；宽屏 32px |
| 标题与内容 | 24px |
| 卡片内边距 | 20px |
| 卡片之间 | 16px |
| 卡片内部元素 | 12–16px |
| 表单字段间距 | 16px |
| 表头单元格上下内边距 | 各约 8px |
| 数据行普通单元格上下内边距 | 各 12px |
| 数据行操作列单元格上下内边距 | 各 6px，容纳 32px 按钮 |

### 控件内容盒与边界安全区

- 控件内边距按视觉和交互角色适用，不按 HTML 标签或组件名称适用。看起来像输入框、下拉框或日期筛选器的控件，即使由 `button`、`Combobox` 或自定义组件实现，也必须使用字段类控件规则。
- 控件高度、文字、图标、内边距和内容间距共同构成完整尺寸。只规定外高，不规定内容盒，视为未完成组件规范。
- 内边距属于控件结构，不属于可压缩空间。宽度不足时优先增加宽度、换行、截断文字或降级操作，不得缩小内边距、图标间距或让图标贴边。
- 文字与尾部图标分别占用独立空间。图标不得通过绝对定位覆盖文字，也不得紧贴控件边框。
- 同类控件在不同页面必须使用同一角色规则，不得用 `px-*`、负边距或固定宽度在业务页面另造一套间距。

### 圆角

| 组件 | 圆角 |
|---|---:|
| 普通卡片 | 8px |
| 输入框 / 普通按钮 | 6px |
| 小型标签 | 4px |
| 下拉菜单 / 表格容器 | 8px |
| 弹窗 / 大型内容面板 | 10px |

避免过度圆润和胶囊形设计。

## 6. 边框与阴影

| 元素 | 规范 |
|---|---|
| 普通卡片边框 | 1px 柔和浅灰边框 |
| 输入框边框 | 1px 柔和浅灰边框 |
| 分割线 | 1px 极浅灰 |
| 普通卡片阴影 | 轻阴影 |
| 卡片 Hover | 轻微增强阴影 |
| 弹窗阴影 | 柔和中等阴影 |
| 下拉菜单阴影 | 柔和阴影 |
| Tooltip 阴影 | 轻微阴影 |

- 阴影必须克制，不使用厚重或大范围扩散阴影。
- 不给每个容器都添加卡片边框。
- 优先通过留白、背景和层级组织内容。
- Hover 不做明显位移或放大。

## 7. 组件尺寸体系

整体采用标准型尺寸。

| 组件 | 尺寸 |
|---|---:|
| 普通按钮 | 36px 高 |
| 主要按钮 | 36px 高 |
| 小按钮 | 32px 高 |
| 大按钮 | 40px 高 |
| 输入框 | 36px 高 |
| Select | 36px 高 |
| 搜索框 | 36px 高 |
| 标签 | 22–24px 高 |
| Checkbox | 16px |
| Radio | 16px |
| 普通图标 | 16px |
| 导航图标 | 18px |
| 大型操作图标 | 20px |

同类组件保持一致，不得在不同页面随意改变高度。

### 控件角色与内容盒

控件必须按下列角色统一使用内边距。组件优先复用 shadcn/ui，不得另建平行组件体系。

| 角色 | 适用范围 | 高度 | 水平内边距 | 图标与文字间距 |
|---|---|---:|---:|---:|
| `field` | Input、Select、Combobox、DatePicker、搜索框、筛选触发器 | 36px | 12px | 8px |
| `action` | 普通按钮、主要按钮、次要按钮、筛选按钮 | 36px | 12px | 8px |
| `action-sm` | 小按钮 | 32px | 12px | 8px |
| `action-lg` | 大按钮 | 40px | 12px | 8px |
| `icon-action` | 只有图标的按钮 | 32px | 图标距边缘 8px | 不适用 |
| `nav-item` | 展开状态下的侧边栏导航项 | 40px | 12px | 8px |
| `menu-item` | 下拉菜单项、Select 选项、列表操作项 | 36px | 12px | 8px |
| `tag` | 标签、状态徽标 | 22–24px | 8px | 4px |
| `table-cell` | 普通表头和数据单元格 | 表头 40px，数据行 44px | 12px | 不适用 |

- `field` 单行文字使用 20px 行高，36px 高度对应上下各 8px 内容余量。
- 尾部图标占 16px，并在图标与文字之间保留 8px 间距。尾部图标到右边框的距离由控件水平内边距保证。
- 导航收起后，图标在 64px 宽度内居中，不沿用展开状态的左右内边距。
- 表格操作列使用 `icon-action`，左右内边距各 4–6px，垂直内边距各 6px，容纳 32px 按钮。

## 8. 按钮体系

### 视觉风格

采用主次分明型：

- Primary：主题主色实心。
- Secondary：白底、灰色边框。
- Ghost：透明背景。
- Destructive：红色实心。

只保留四种按钮语义类型，不额外引入 Outline、Link 等独立按钮类型。需要弱化的文字链接可使用普通文本链接样式，不扩展按钮体系。

### 统一规则

- 默认高度 36px，小按钮 32px，大按钮 40px。
- 圆角 6px，不使用胶囊形。
- 文字 14px，字重 500。
- 水平内边距 12px。按钮宽度由内边距、文字、图标间距和图标共同决定，不使用会压缩内边距的固定宽度。
- 图标 16px，图标与文字间距 8px。
- 只有图标的按钮使用 32×32px 点击区域，图标距四边各 8px。
- 必须有 Hover、Active、Disabled、Loading 状态。
- 同一区域原则上只设置一个 Primary 主操作。
- 危险操作统一二次确认。
- 确认内容应明确操作对象和后果。

## 9. 表格体系

| 维度 | 规范 |
|---|---|
| 视觉风格 | 极简分割线型 |
| 默认数据行高 | 44px，内容超出时自动增高 |
| 表头高度 | 固定 40px |
| 表头背景 | 极浅灰色 |
| 表头字体 | 13px，字重 500 |
| 数据字体 | 14px |
| 行 Hover | 浅蓝灰背景 |
| 行选中 | 浅蓝背景 |
| 分割线 | 1px 极浅灰 |

### 表格交互与约束

- 默认不使用纵向网格线。
- 默认不使用斑马纹。
- 不给每个单元格添加独立边框。
- 支持排序、Checkbox 多选、固定表头和统一分页。
- 固定操作列按需启用。
- 操作按钮尽量使用 Ghost，避免操作列拥挤。
- 长文本可按需截断。完整内容须能通过键盘和触屏查看，例如在可聚焦的元素上显示提示，或提供可点击的展开入口。
- 数字、金额、数量等数据保持合理对齐。
- 普通单元格上下内边距各 12px。操作列上下各 6px，容纳 32px 按钮。
- 表头单元格和普通数据单元格左右内边距各 12px。操作列左右内边距各 4–6px，为 32px 图标按钮预留空间。
- 表头排序图标、状态标签和行内操作必须占用布局空间，不得紧贴单元格边界或覆盖文字。
- 数据行内容超出 44px 时自动增高，保持控件完整尺寸和可见性。复杂业务表格可提供紧凑模式，同样须让数据行按内容增高。

## 10. 表单体系

### 布局

- 双列网格为主。
- 复杂字段、长文本、明细表格使用单列。
- Label 统一放在输入框上方，不在同一表单内混用左右标签布局。

### 输入组件

| 元素 | 规范 |
|---|---|
| 输入框高度 | 36px |
| 圆角 | 6px |
| 边框 | 1px 柔和浅灰 |
| 输入文字 | 14px |
| Label | 14px，字重 500 |
| 字段间距 | 16px |
| 字段类控件左右内边距 | 12px |

- `field` 角色适用于 Input、Select、Combobox、DatePicker、搜索框和所有由其他元素实现的筛选触发器。
- 字段类控件高度 36px，单行文字行高 20px。左侧图标、右侧清空按钮或下拉箭头均占独立空间，图标与文字间距 8px。
- 日期范围、较长的选项名称等内容必须获得足够宽度。空间不足时允许控件增宽、文字截断后提供 Tooltip，或让筛选区换行，不得压缩左右内边距。
- 清空、日历、Loading 和下拉箭头出现或消失时，不为控件重新分配内边距，避免文字位置跳动。

### 状态与提交

- 必填字段统一使用红色 `*` 标识。
- Focus 使用主题焦点色，默认使用科技蓝。
- Disabled 状态明确降低视觉对比度。
- Error 在对应字段下方显示具体错误原因。
- 页面表单使用底部固定操作栏；必须预留底部空间，不能遮挡表单内容。
- 弹窗表单的操作按钮放在底部右侧。
- 弹窗内容合理滚动，底部操作区保持可见。
- 表单保存或提交成功后使用 Toast 提示。

## 11. 图标体系

- 图标库：Lucide React。
- 视觉风格：线性 Outline。
- 普通图标 16px；导航图标 18px；大型操作图标 20px；空状态图标 32–48px。
- 默认中性灰，激活状态使用主题主色。
- 成功、警告、危险状态分别使用绿色、橙色、红色。
- 不混用其他图标库。
- 不使用 Emoji 或 Unicode 字符代替功能图标。
- 同一功能在全系统使用一致图标。
- 图标必须有明确功能含义，禁止纯装饰性使用。

## 12. 页面布局

### 整体结构

采用左侧固定导航 + 顶部固定导航 + 自适应主内容区。

| 区域 | 规范 |
|---|---|
| 侧边栏宽度 | 240px |
| 侧边栏收缩宽度 | 64px |
| 顶部导航高度 | 56px |
| 顶部导航 | 固定定位 |
| 主内容区 | 自适应宽度 |
| 页面左右边距 | 24px；宽屏 32px |

### 侧边栏

- 白色背景，右侧 1px 浅灰边框。
- 导航项高度 40px，展开状态左右内边距 12px，圆角 6px。
- 支持分组、二级菜单和收缩。
- 当前选中项使用主题主色的浅色背景，文字和图标使用主题主色。
- Hover 使用浅灰背景。
- 不使用彩色渐变侧边栏。

### 顶部导航

- 白色背景，底部 1px 浅灰分割线。
- 左侧放置面包屑 / 页面路径。
- 右侧放置全局搜索、通知、用户菜单等全局入口。
- 控制入口数量，避免顶部拥挤。

### 主内容与滚动

- 主内容区域使用浅灰背景。
- 避免设置过小的全局 max-width。业务表格和复杂明细页应充分使用可用宽度。
- 普通设置页可按内容需要限制宽度。
- 顶部导航固定；侧边栏与主内容独立滚动。
- 表格必要时允许内部横向滚动。
- 避免无意义的双重滚动条。

## 13. 状态反馈体系

### Loading

- 页面首次加载使用 Skeleton。
- 局部操作使用 Spinner。
- 按钮提交使用按钮内部 Loading。
- Skeleton 尽量匹配真实内容结构，避免布局跳动。
- 避免整页长时间只显示单个旋转图标。

### Empty

- 使用简洁线性图标 + 说明 + 可选操作按钮。
- 有创建权限时提供创建入口。
- 不使用大型装饰插画。

### Error

分别处理页面级、局部和字段级错误：

- 页面级错误：清楚说明问题，并在可行时提供重试。
- 局部错误：在对应内容区域显示。
- 字段级错误：在字段下方显示具体原因。
- 错误信息应尽可能说明原因和下一步操作。

### Toast

- 位置：右上角。
- 默认 3 秒自动消失。
- Success 绿色、Error 红色、Warning 橙色、Info 蓝色。
- 创建、保存、提交等操作明确完成后，用 Toast 提示成功。筛选、切换等即时操作默认不显示成功 Toast。
- Toast 不得替代重要错误处理或必须由用户处理的确认流程。

### Tooltip

- 支持鼠标悬停、键盘聚焦和触屏操作。触屏可通过点按可见的提示入口触发。
- 触发后等待 300 ms，随后用 150 ms 淡入，遵循减少动态效果设置。
- 用于解释图标按钮、字段含义和缩略内容。完整内容须可通过键盘和触屏查看。
- 不展示大段说明文字。

### Confirmation

- 危险操作统一二次确认。
- 重要不可逆操作要求输入对象名称确认。
- 明确展示操作对象和后果。
- 普通操作不要频繁弹窗打断用户。

## 14. 图表与数据可视化体系

### 视觉风格

采用极简科技风：

- 白色或浅灰背景。
- 细网格线。
- 主数据系列使用统一的图表主题令牌，默认使用科技蓝。
- 语义辅助色克制使用。
- 图表优先突出数据，不追求装饰效果。

### 数据颜色

| 用途 | 颜色 |
|---|---|
| 主数据系列 | 默认科技蓝 `#2563EB` |
| 辅助系列 | 青色 `#06B6D4` |
| 上升 / 增长 | 红色 `#DC2626` |
| 需关注 | 橙色 `#F59E0B` |
| 下降 / 回落 | 绿色 `#16A34A` |
| 次要数据 | 灰色 `#9CA3AF` |

- 不为每条数据随机分配颜色。
- 同一指标在不同页面保持相同颜色含义。
- 指标变化统一采用红升绿降（上升用红色，下降用绿色，需关注用橙色）。
- 仅在有明确数据含义且配有图例时使用功能性渐变，颜色遵循总体设计规范。

### 图表类型

常用图表完整支持，按业务问题选择，不强制使用所有类型：

- 折线图：趋势、时间变化。
- 柱状图：数量、分类对比。
- 饼图 / 环形图：占比、构成。
- 面积图：累计量、规模变化。
- 横向柱状图：排名、长分类名称。
- 堆叠柱状图：不同状态或渠道构成。
- 散点图：指标相关性。
- 漏斗图：业务转化链路。
- 热力图：时间和密度分布。

### 图表容器与交互

- 图表容器使用白色背景，并遵循普通卡片边框和圆角规范。
- 普通图表高度 280–360px。
- 图表标题默认 16px，字重 600，优先于通用卡片标题的 20px 默认值，并遵循同一视口的四种字号上限。
- 图例放在图表上方或下方。
- 图表 Tooltip 遵循状态反馈章节的触发与显示规则。
- 按需支持时间筛选、数据筛选和图例切换。
- 数据量过大时使用分页、聚合或采样。

### KPI 指标卡片

统一支持 KPI 指标卡片：

- 指标名称 13–14px。
- 核心数字 24–30px。
- 数字启用等宽数字特性（Tabular Numbers）。
- 显示变化值及比较周期。
- 趋势颜色采用红升绿降（上升用红色，下降用绿色）。
- KPI 卡片不应堆叠过多装饰元素。

## 15. 动效与交互规范

### 动效风格

采用极简克制型（Minimal Motion），动效只用于帮助用户理解状态变化和操作结果，不作为装饰。

- 默认动效时长为 150–200ms。
- 按钮 Hover：颜色轻微变化，不放大、不跳动。
- 点击反馈：Active 状态即时响应。
- 弹窗：轻微淡入，约 200ms，不使用夸张缩放。
- 下拉菜单：轻微淡入，约 150ms。
- Tooltip：触发后等待 300 ms，淡入 150 ms。
- 展开 / 折叠：使用平滑高度过渡。
- 页面切换：不使用复杂转场。
- Loading：使用 Spinner 或 Skeleton。
- 成功 Toast 按状态反馈章节的规则使用。
- 操作失败：明确展示错误原因。

### 动效约束

- 不使用弹跳、夸张缩放、持续循环的装饰动画。
- 不使用明显的位移或放大来表达普通 Hover。
- 动效必须服务于状态反馈、空间关系或操作理解。
- 支持 `prefers-reduced-motion`；用户启用减少动态效果时，关闭或弱化非必要动画。
- 不得因动画延迟真实操作反馈。

## 16. 响应式设计规范

### 整体策略

采用**桌面优先（Desktop-first）**，同时保证平板和手机端可用。

移动端优先保障用户在手机上的核心任务。各项目按实际使用场景确定移动端支持的业务流程。

### 断点体系

采用 Tailwind 默认断点：

| 设备 | 屏幕宽度 | 布局策略 |
|---|---:|---|
| Mobile | 小于 640px | 单列布局 |
| Tablet | 640–1023px | 紧凑布局 |
| Desktop | 1024–1279px | 标准后台布局 |
| Wide Desktop | 1280px 及以上 | 完整后台布局 |

### 导航适配

- 桌面端（≥1024px）：左侧固定导航，默认宽 240px，可收缩至 64px。
- 平板端（640–1023px）：默认使用收缩侧边栏，主内容自适应。
- 手机端（<640px）：侧边栏改为抽屉式导航，通过菜单按钮打开。
- 顶部导航在手机端隐藏次要入口，保留菜单和核心操作。

### 页面内容适配

- 桌面端：保持标准后台布局，表单双列为主，复杂表格充分利用可用宽度。
- 平板端：根据可用宽度将表单调整为单列或双列。
- 手机端：表单统一单列；主要操作按钮可根据场景占满宽度。
- KPI 指标卡片：桌面端多列，平板端两列，手机端一列或两列，按内容可读性决定。
- 图表宽度自适应，保持合理可读高度，不得挤压图表内容。
- 弹窗桌面端居中；手机端采用接近全屏的布局。

### 手机端复杂表格

- 默认保留表格结构，支持横向滚动。
- 不得为了适配窄屏而把所有列压缩到不可读。
- 优先保证关键字段和操作入口可发现。
- 如果表格横向滚动，应确保用户能理解还有更多列，并避免页面整体意外横向溢出。
- 不默认把表格每一行转换为卡片；只有在具体任务明确要求且卡片更适合阅读时才采用。

### 手机端业务功能范围

手机端采用核心功能支持策略：

- 支持数据查看、查询、搜索和筛选。
- 支持适合移动端的简单操作。
- 复杂业务操作是否适配移动端，由具体项目按用户需求和操作场景决定。
- 移动端适配需保证业务操作的准确性和可用性。

## 17. 技术实施约束

- Tailwind CSS + shadcn/ui。
- 优先复用项目已有 UI 组件。
- 使用 CSS variables / design tokens 管理颜色、圆角、阴影等基础视觉属性。
- 不在业务组件中散落硬编码颜色。
- 不引入与现有项目重复的图标库或组件库。
- 保持组件 API 一致，避免同类组件出现多套实现。
- 将控件水平内边距和图标间距收敛为共享 token，并在现有基础组件中统一应用。业务页面不得直接覆盖这些值。
- 需要自动检查时，可为基础组件增加 `data-ui-kind="field|action|icon-action|nav-item|menu-item|tag|table-cell"`。该属性只用于设计验收，不替代原生语义或 ARIA 属性。
- 适配项目已有的主题机制；默认 Light Mode。
- 对新增组件提供必要的键盘交互、焦点状态和可访问标签。

## 18. 开发完成后的视觉检查

完成 UI 工作后，实际运行并查看页面，不得仅凭代码推断视觉效果。

检查清单：

- [ ] 是否符合 Light Minimal Tech 风格？
- [ ] 是否避开了紫色、蓝紫色和装饰性渐变？功能性渐变是否有明确的数据含义和图例？
- [ ] 是否复用了现有 shadcn/ui 组件？
- [ ] 是否使用统一 CSS 设计令牌，遵循品牌色优先级并保留既有品牌主题配置？
- [ ] 次级文字在实际背景上是否满足普通文字对比度要求？
- [ ] 同一视口是否最多使用四种字号，并保留规定的文字层级？
- [ ] 是否存在卡片套卡片或无意义边框？
- [ ] 按钮、输入框和表格尺寸是否符合规范？操作列是否容纳 32px 按钮，数据行是否能随内容增高并完整显示控件？
- [ ] 字段类控件、按钮、菜单项、导航项和标签是否使用对应角色的水平内边距？文字和图标到边界的最小距离是否达到规范值？
- [ ] 带尾部图标的字段是否同时保留 8px 图标间距和 12px 右侧安全区？图标是否使用独立布局空间而不是绝对定位贴边？
- [ ] 表头与普通数据单元格左右内边距是否为 12px？操作列是否使用 4–6px 内边距容纳 32px 图标按钮？
- [ ] 表格是否保持极简分割线风格？
- [ ] 表单是否按断点验收？桌面端（≥1024px）以双列为主，复杂字段、长文本和明细表格用单列。平板端（640–1023px）按可用空间用单列或双列。手机端（<640px）统一单列。
- [ ] 图标是否统一使用 Lucide Outline？
- [ ] 侧边栏、顶栏和主内容区尺寸是否符合规范？
- [ ] 是否按需覆盖 Loading、Empty、Error、Toast 和 Confirmation，成功 Toast 是否仅用于明确完成的操作？
- [ ] Tooltip 是否支持鼠标、键盘和触屏，触发后等待 300 ms，默认淡入 150 ms？截断文本的全文是否可通过键盘和触屏查看？
- [ ] 启用 `prefers-reduced-motion` 时，Tooltip 淡入和其他非必要动效是否减弱或关闭？
- [ ] 指标趋势颜色是否按红升绿降（及橙色需关注）使用？
- [ ] 是否检查了不同屏幕宽度下的布局？
- [ ] 宽度不足时是否通过换行、增宽或截断文字处理，而不是压缩控件内边距？
- [ ] 是否在 375px、768px、1280px 以及 200% 缩放下检查了字段和表格内容不被边框挤压、截断或覆盖？
- [ ] 是否实际查看了页面并修复明显的视觉问题？

只有实际查看过页面后，才能报告视觉验证通过。若没有运行或无法查看，应明确说明未完成视觉验证。
