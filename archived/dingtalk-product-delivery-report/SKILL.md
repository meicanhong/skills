# 钉钉产品交付报告

## 目标

实时核对通讯录、项目表与员工日志，只输出一张老板决策表。报告用于判断交付是否可靠，不用于员工绩效评分。

必须保持只读：不创建、修改或删除钉钉文档、日志、通讯录或审批数据。

## 工作流

### 1. 确认输入

默认从 `scripts/.env` 读取凭证。该文件必须仅允许当前用户读取，不得写入报告或复制到其他产物。

凭证优先级从高到低：

1. 环境变量 `DWS_CLIENT_ID`、`DWS_CLIENT_SECRET`
2. 用户明确通过 `--credentials-file` 传入的文件
3. Skill 自带的 `scripts/.env`

这些变量名是当前企业内部应用沿用的命名，不代表调用 DWS。实际只调用钉钉 HTTP API。

不得在命令、日志、报告或错误信息中回显 client secret、access token。不要 `source` 用户提供的凭证文件。

默认企业范围、部门名称、项目表和排除人员见 `references/default-scope.json`。默认不把静态 userId 列表当作产品部实时范围；用户明确指定其他表、人员或项目时，优先使用用户范围。

### 2. 实时获取数据

运行：

```bash
python3 scripts/fetch_delivery_context.py \
  --output "/tmp/dingtalk-delivery-context.json"
```

正常运行不需要传凭证参数。如需临时使用另一套应用凭证，再传 `--credentials-file`。

可选参数：

- `--as-of YYYY-MM-DD`：报告基准日，默认 Asia/Shanghai 当天
- `--log-days N`：日志窗口，默认 14 天
- `--cutoff-days N`：近期交付窗口，默认未来 30 天
- `--project NAME`：重复传入以限定项目；默认不限定具体项目名
- `--user-id ID`：重复传入以覆盖默认员工范围
- `--config PATH`：覆盖默认企业配置

默认项目范围不是配置文件里写死的三个项目，而是实时按以下顺序确定：

1. 从通讯录递归查找名称完全等于“产品开发&供应链”的部门。
2. 实时读取该部门直属人员；默认不含下级部门，并排除王维。
3. 读取《电商产品进度》整表。
4. 只保留状态为“进行中”，且到仓日在报告基准日或此前、或不晚于未来 30 天截止日的项目；到仓日缺失的进行中项目也保留并标记待核验。
5. 只有用户显式传入 `--project` 时，才进一步限定项目名称。

脚本必须完成通讯录、项目表和所有日志分页，并在输出的 `completeness` 中记录读取来源、页数、条数、`has_more` 和 `complete`。若任何用户未读完、通讯录或项目表读取失败，不得生成“已核验”的结论；先报告具体缺口。

### 3. 生成报告

完整读取 `references/report-rules.md`，严格按其中的证据、风险和格式规则判断。

必须交叉核对：

1. 项目表的交付日期、状态、负责人和备注。
2. 最近 14 天日志中实际完成的动作。
3. 实际生产数量、到仓数量、质量验收和剩余差额/最终日期。
4. 表与日志冲突、过期未更新、重复汇报和未上报风险。

项目表决定“有哪些项目”和计划基线；日志只能补充实际进展，不能凭日志新增一个不在近期项目范围内的项目。

日志关联分两级：

- `matched_projects`：日志直接出现项目全名或明确别名，可作为直接关联线索。
- `related_project_hints`：只出现供应商、品类或风险词，仅是检索提示；必须结合日志同一编号段落、负责人和项目表备注才能归到某项目，不能单独作为证据。

“当前进度”只能写已经完成且有证据的事项，不写计划、意向或“推进中”。每个单元格使用 `1. 2. 3.` 编号，最多三条，按离交付结果最近的证据排序。

### 4. 输出约束

最终只输出以下一张 Markdown 表格，不加老板结论、背景说明、证据附录或管理点评：

| 项目 | 日期 | 风险程度 | 责任人 | 当前进度（已完成） | 风险点 | 需要老板拍板决策什么？ |
|---|---|---|---|---|---|---|

单元格内使用 `<br>` 换行。风险程度只允许：

- `🔴 红色`
- `🟡 黄色`
- `🟢 绿色`
- `⚪ 待核验`

责任人优先写项目 PM；日志中有明确承担交付动作的协作人时写成“PM：姓名；协作：姓名”。不得依据谁写了日志就自动认定谁是责任人。

没有证据时直接写“未提供”或“待核验”，不得把“没有记录”写成“没有工作”。

## 失败处理

- 鉴权失败：只说明钉钉错误码和错误信息，不展示请求 URL、凭证或 token。
- 单个员工无权限：保留其他读取结果，但整份报告标记相应证据“待核验”，不得声称日志已完整覆盖。
- 项目表与日志冲突：风险程度使用 `⚪ 待核验` 或按已确认的关键阻塞判红，并在风险点写清冲突双方，不擅自选择一方。
- 用户点名的项目在项目表中找不到：仍输出该项目一行，日期、责任人和进度按“未提供”，风险程度为 `⚪ 待核验`。
