## 状态定义

| 状态 | 含义 |
|---|---|
| 通过 | 所需字段和可验证证据一致。 |
| 失败 | 满足本文件列出的确定性失败条件，报告为不建议通过。 |
| 警告 | 存在风险或材料不理想，但不足以认定确定性失败。 |
| 无法判断 | 缺少可验证证据、语义不明确或规则不适用，交人工复核。 |

“原始证据”指脱敏后的 `来源类型 + 稳定资源 ID + 字段路径/字段名 + 原值片段`，不是完整 JSON、文档全文或响应转储。

## 规则模型

每条规则统一表示为：

| 属性 | 要求 |
|---|---|
| 规则 ID | 稳定且唯一，例如 `PAY-003`。 |
| 目标字段 | OA 字段名或明确业务字段，不用模糊的“整体情况”。 |
| 检查描述 | 写清期望条件、比较方法和边界。 |
| 证据来源 | OA 字段、图片 ID、审批实例、文档 ID、附件 ID、合同 ID、AI 表格 `recordId` 等。 |
| 判定方式 | 精确计算、稳定 ID 匹配、明确文本字段比较或辅助视觉判断。 |
| 失败级别 | 确定性失败、警告或仅人工复核。 |

示例：

```text
规则 ID：PAY-003
目标字段：支付金额（元）
检查描述：申请金额必须等于审批明确引用的全部费用明细合计，差额必须为 0.00。
证据来源：OA processInstanceId + AI 表格 recordId 列表 + 金额字段
判定方式：十进制定点求和与精确比较
失败级别：确定性失败
```

自然语言规则如果缺少明确字段、可验证期望或稳定证据来源，只能标记警告或无法判断。

## 通用规则

| 规则 ID | 检查项 | 通过 | 确定性失败 | 警告或无法判断 |
|---|---|---|---|---|
| GEN-001 | 实例身份与状态 | 能确定实例 ID、模板、发起人、部门、发起时间和当前状态。 | 不适用。 | 必要元数据缺失为无法判断；非当前待审批实例强制只读。 |
| GEN-002 | 关联资料可读性 | 明确关联的资料均成功读取并完成内容解析，或审批明确表示无关联资料。 | 不适用。 | 明确资料下载信息获取、下载或解析失败为运行错误/无法判断；没有明确关联但推测应有资料为警告。 |
| GEN-003 | 附件可追溯 | 附件有名称、类型、数字 `fileId` 和 `spaceId`，并分别记录下载信息、下载、类型校验和内容解析状态。 | 不适用。 | 标识不完整、凭证/权限缺失、下载失败或解析失败为无法判断/运行错误。 |
| GEN-004 | 模板支持 | 能将模板归入已知核查类型并找到关键字段。 | 不适用。 | 未知模板固定人工复核。 |
| GEN-005 | 图片证据 | 规则涉及的图片或扫描 PDF 已通过 OA 附件下载链路实际读取，且 `fileId`、页码/画面和结论可定位。 | 仅图片不能独立构成通用确定性失败。 | 未取得下载信息、未下载、未渲染、模糊、OCR 有歧义或只有临时 URL 时为无法判断。 |
| GEN-006 | 同模板历史 | 已在规则限定时间窗和企业应用授权范围内完成稳定 ID 查询。 | 仅按专项规则认定重复时失败。 | 可见范围不足、无法查询或仅内容相似时为警告/无法判断。 |
| GEN-007 | 平台 AI 提示 | 已记录平台返回的提示并由本 Skill 独立复核。 | 平台 AI 提示本身不构成确定性失败。 | 只作为参考；API 未返回时写“未返回”，不推断客户端无提示。 |

## 付款申请专项规则

关键付款字段：收款人、付款事由、有效申请金额、期望付款时间。金额必须能解析为大于 0、最多两位小数的十进制数。

| 规则 ID | 检查项 | 通过 | 确定性失败 | 警告或无法判断 |
|---|---|---|---|---|
| PAY-001 | 关键字段 | 四个关键字段均存在且金额有效。 | 任一关键字段明确缺失，或金额为空、非数字、为零/负数、精度无效。 | 字段标签语义不明为无法判断，不猜测映射。 |
| PAY-002 | 明细数量 | OA 明确引用的数量等于稳定关联记录的数量。 | OA 明确给出明细范围/数量，且可完整读取的稳定记录数量不等。 | 关联范围不明确、表格未读全或记录无稳定 ID为无法判断。 |
| PAY-003 | 明细金额 | 明细十进制合计与 OA 申请金额完全一致，差额为 0.00。 | OA 明确引用的明细已完整读取，但合计与申请金额不一致。 | 明细缺失、不可读或关联不明确为无法判断/运行错误。 |
| PAY-004 | 重复报销 | 稳定 `recordId` 对应费用没有已报销标记，或有明确非重复说明。 | 同一稳定 `recordId` 被明确标记为其他已报销批次/审批，且当前申请再次引用同一费用。 | 只有描述、金额或日期相似而无稳定 ID，只能警告。 |
| PAY-005 | 合同主体 | 明确关联合同的付款方/收款方与申请双方一致。 | 明确关联合同中与本次付款对应的签约或收款主体，与申请主体明确不一致。 | 仅名称简称或别名无法确认时为无法判断。 |
| PAY-006 | 合同金额 | 合同明确标注的“本次应付金额/本期付款金额”与申请金额一致。 | 明确关联合同或付款计划的本次应付金额与申请金额不一致。 | 只有合同总额、没有本次应付金额时，不得直接比较为失败；标记无法判断或警告。 |
| PAY-007 | 合同与付款时间 | 明确付款节点允许在期望付款日付款。 | 仅在材料明确写出禁止该时点付款且没有例外时，才可失败。 | 付款申请发起时间晚于期望付款时间、时间倒挂或节点含糊，只警告。 |
| PAY-008 | 发票 | 发票材料可追溯，或合同/制度明确允许后补。 | 不适用。 | 无发票、发票未到或无法判断发票要求，只警告。 |
| PAY-009 | 推测应有合同 | 有明确合同链接则按 PAY-005 至 PAY-007 核查。 | 不适用。 | 仅凭金额或事项推测应有合同，只警告。 |

## 可复用规则示例

以下示例用于帮助识别规则结构，不得脱离实际模板和证据直接判失败：

| 场景 | 目标字段 | 检查描述 | 证据要求 |
|---|---|---|---|
| 付款申请 | 支付金额 | 等于明确关联明细合计。 | 实例 ID、完整 `recordId` 列表、金额字段。 |
| 付款申请 | 收款人 | 等于明确关联合同的本次收款主体。 | 合同 ID、合同主体字段、OA 收款人字段。 |
| 报销申请 | 费用明细 | 同一稳定费用记录不得被其他报销批次再次引用。 | 当前实例、费用 `recordId`、其他批次/实例稳定 ID。 |
| 采购申请 | 采购金额 | 等于发票或合同明确标注的本次采购金额。 | 可读附件/文档稳定 ID及对应金额字段。 |
| 请假申请 | 请假天数 | 在限定时间窗内的同模板累计天数不超过明确上限。 | 同模板、同申请人、时间窗、历史实例 ID。 |
| 证明图片 | 图片字段 | 图片中必须清楚出现规则指定的证明要素。 | 稳定图片 ID、清晰画面、明确要素；视觉歧义时人工复核。 |

## 确定性失败的约束

只有 PAY-001 至 PAY-007 中“确定性失败”列明确命中的情况才可报告为确定性失败。必须同时满足：

1. 期望值和实际值都来自可定位字段，或期望值来自本文件的明确格式约束。
2. 关联记录已完整读取，分页没有遗漏。
3. 证据使用稳定的实例 ID、文档 ID、附件 ID 或 `recordId`。
4. 差异不是由四舍五入、别名、分期付款或未知业务语义造成。

PAY-004 的失败证据至少包含当前费用 `recordId`、已报销批次/审批的稳定标识，以及当前审批对同一 `recordId` 的引用。只有“名称相似”“金额相同”或“日期接近”不得认定重复。

## 报告格式

默认只输出口语化短报告。完整规则计算、证据定位和能力状态在内部保留，不要因为默认不展示而省略核查。

```text
这笔<审批类型>有<数量>个明显问题，<先别批 | 需要人工复核>：

- <申请内容与证据内容的关键差异>
- <第二个关键差异；没有则省略>

<最多一句重要警告；没有则省略>

我没有操作审批。建议<下一步>。
```

短报告只列影响结论的 1 至 3 个关键点，不显示规则编号、检查计数、能力覆盖、证据指纹、附件处理过程或逐项通过记录。不得用简短输出掩盖读取失败；证据不足时直接说“这个材料没读到/看不清，需要人工确认”。

用户明确要求查看证据、详细说明、能力覆盖、规则明细或审计报告时，使用下面的详细格式：

```text
风险总览
- 检查：<总数> 项
- 通过：<数量> 项
- 失败：<数量> 项（其中确定性失败 <数量> 项）
- 警告：<数量> 项
- 无法判断：<数量> 项

审批实例：<processInstanceId>
模板：<模板名>
发起人 / 部门：<姓名> / <部门>
发起时间：<ISO-8601>
结论：<可以人工通过 | 可以人工通过（含警告） | 不建议通过 | 人工复核 | 运行错误，需人工复核>
OA 操作：未执行

能力覆盖
- 审批字段：<已核查 | 未提供 | 能力不支持 | 权限或读取失败>
- 图片：<状态 + 数量 + 说明>
- 同模板历史：<状态 + 时间范围 + 可见范围说明>
- 关联文档：<状态>
- AI 表格：<状态>
- 普通附件：<状态>

平台 AI 参考
- <未返回 | 风险数量与脱敏摘要；仅供参考>

付款摘要
- 收款人：<脱敏值>
- 付款事由：<值>
- 申请金额：<金额>
- 期望付款时间：<时间>

关联资料
- 文档：<类型 + documentId/nodeId + 读取状态>
- AI 表格：<baseId/tableId + recordId 列表或范围 + 读取状态>
- 附件：<名称 + 类型 + fileId/spaceId + 下载信息/下载/类型校验/内容解析状态>

金额核对
- 明细数量：<数量>
- 明细合计：<金额>
- 申请金额：<金额>
- 差额：<金额>

规则结果
- [<状态>] <规则 ID> <检查项>
  目标字段：<字段>
  检查描述：<规则>
  证据来源：<来源类型>
  期望值：<值>
  实际值：<值>
  原始证据：<来源 + 稳定 ID + 字段名/路径 + 脱敏原值>
```

不适用于当前模板的付款字段写“不可用”，不要伪造空值。历史审批回放在短报告末尾或详细报告结论后追加“只读回放：不会产生 OA 写操作”。

## 验证场景

- 当前无待审批：唯一输出为 `暂无待审批`，并立即结束。
- 金额不一致：PAY-003 为失败，默认短报告说明差额、证据和“未执行 OA 操作”。
- 关联资料不可读：GEN-002 为运行错误，停止依赖该资料的判定。
- 未知模板：GEN-004 为无法判断，输出通用证据摘要并人工复核。
- 图片不可读取：GEN-005 为无法判断，能力覆盖标记“权限或读取失败”，不把图片规则视为通过。
- 自有应用凭证未配置：继续核查 OA 字段，普通附件标记“权限或读取失败”，总体至少人工复核，不要求用户在对话中粘贴密钥。
- 普通下载信息接口明确返回权限不足：核对已验证权限组合，保留脱敏错误；不改用 Premium、浏览器或调用层手工下载签名地址。
- Premium 权限已授权但企业未开通 OA 高级版：回到普通接口；不得把 Premium 权限状态当成产品权益状态。
- 普通钉盘目录列举 OA 附件空间返回 `forbidden.accessDenied`：不得据此判定审批附件不可下载，继续按 OA 普通下载信息主路径处理。
- 附件下载信息获取与下载成功：分别校验非空、真实类型和内容解析状态；下载成功本身不等于规则通过。
- 多类型附件回放：TXT、JSON、CSV、XLSX、DOCX、PPTX、PNG、JPG、文本 PDF、扫描 PDF、ZIP 应能完成下载信息获取与下载，测试 fixture 应与原件逐字节一致。
- 同模板历史不可见：GEN-006 为无法判断，明确可见范围，不输出“未发现历史重复”。
- 平台 AI 提示存在风险：GEN-007 记录为参考，再独立执行本 Skill 规则；仅平台提示不构成确定性失败。
- 已完成的 13,766.01 元付款申请只读回放：应定位费用序号 17–34，共 18 笔，明细合计 13,766.01 元；异常证据必须引用稳定 `recordId`，不得仅凭序号或描述判重复。
