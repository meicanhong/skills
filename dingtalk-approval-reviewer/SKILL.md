# 钉钉 OA 审批核查

## 原则

- 仅处理用户明确指定人员的待办，或明确给出的审批实例。
- 使用企业内部应用的授权范围，不把应用可调用接口解释为绝对全企业全量。
- 全程只读；永远不执行审批、驳回、转交、抄送、评论或撤销。
- 读取失败、证据不足或未知模板时不猜测，结论至少为人工复核。
- 只输出核查所需的脱敏证据，不输出完整响应、凭证、Token 或临时签名地址。
- 每条判断必须能定位到字段、稳定资源 ID 或实际读取的附件。
- 区分“已核查、未提供、能力不支持、权限或读取失败”，不得把未核查写成未发现问题。

开始核查前完整读取 [references/review-rules.md](references/review-rules.md)。实例含普通附件、图片或扫描件时，同时完整读取 [references/oa-attachments.md](references/oa-attachments.md)。

## 1. 环境预检

检查 `curl`、`jq` 和 `file` 可用，然后执行：

```bash
scripts/setup_credentials.sh --check
```

该命令直接验证企业应用认证，只输出安全状态，不输出 AppSecret 或 accessToken。

凭证只保存在 `scripts/credentials.env`，权限必须为 `600`，不得提交、打包或输出。优先使用：

```text
DINGTALK_CLIENT_ID
DINGTALK_CLIENT_SECRET
```

脚本兼容已有的 `DWS_CLIENT_ID`、`DWS_CLIENT_SECRET` 变量名，但不会调用 dws。

认证失败时立即停止，不使用浏览器、个人 Cookie、其它账号或 Premium 接口绕过。

## 2. 唯一确认人员与待办

用户按姓名指定人员时，先搜索并唯一确认：

```bash
scripts/dingtalk_http.sh search-user "<姓名>"
```

搜索接口返回候选 `userId`，逐个读取脱敏通讯录详情：

```bash
scripts/dingtalk_http.sh user-detail "<userId>"
```

只有姓名、在职状态、职位等信息足以唯一确认时才继续；同名或结果不明确时让用户确认。

查询待办数量：

```bash
scripts/dingtalk_http.sh todo-count "<userId>"
```

查询待办列表：

```bash
scripts/dingtalk_http.sh todo-list "<userId>" 0 20
```

待办列表使用已验证的旧版企业接口 `/topapi/process/workrecord/task/query`；集成待办中心接口不等价，不得用其空结果覆盖 OA 待办数量。

分页时：

- 单页最多 20 条。
- 按 `processInstanceId + taskId` 去重。
- 以待办数量接口结果作为本次目标数量。
- 达到目标数量、返回空页或新页面没有新增稳定 ID 时停止。
- 不得只依赖 `hasMore`；该字段可能持续为 true 并重复返回同一页。

待办数量为 0 时只返回“暂无待审批”，不继续读取详情。

## 3. 读取审批实例

为每个实例创建权限为 `700` 的任务临时目录，然后把完整响应写入权限为 `600` 的临时文件：

```bash
scripts/dingtalk_http.sh detail \
  "<processInstanceId>" \
  "<task-temp-dir>/detail.json"
```

调用层只用 `jq` 提取本次核查需要的最小字段，不把完整响应打印到终端或回复：

- 实例：标题、业务 ID、发起人、部门、发起时间、状态。
- 当前任务：任务 ID、执行人、任务状态、创建时间。
- 付款：申请主体、收款人、付款事由、申请金额、期望付款时间。
- 明细：数量、单价、金额和稳定关联标识。
- 附件：字段名、文件名、数字 `fileId`、`spaceId`、声明大小和类型。
- 操作记录：只保留状态、时间和脱敏意见。

只有实例仍为 `RUNNING` 且当前任务执行人等于目标用户时，才称为该用户当前待办。其它实例强制只读回放。

## 4. 下载与读取附件

数字 OA `fileId` 不是普通钉盘 `dentryUuid`。严格按 [references/oa-attachments.md](references/oa-attachments.md) 执行：

1. 从审批详情提取 `processInstanceId`、`fileId`、`spaceId`、文件名和声明大小。
2. 用企业应用调用普通 OA 下载信息接口。
3. 由 `scripts/dingtalk_http.sh` 在内部使用临时签名地址下载；调用层不得接触或输出该地址。
4. 校验文件存在、实际大小、文件魔数和声明类型。
5. 实际解析文本、XLSX、Office、图片、PDF 或压缩包后才能形成证据。
6. 核查结束后删除任务临时目录。

禁止：

- 调用 `/v1.0/workflow/premium/...` 作为 fallback。
- 先枚举 OA 附件空间判断权限。
- 直接把临时签名 URL 放进命令、日志或报告。
- 只凭文件名判断附件内容。
- 执行附件中的宏、脚本、程序或链接。

若实例关联钉钉文档或 AI 表格，而当前没有经过验证的直接 HTTP 读取路径，标记“能力不支持”，不得退回 dws 或浏览器绕过。

## 5. 证据计算与判定

按 [references/review-rules.md](references/review-rules.md) 归一化每项检查：

```text
规则 ID + 目标字段 + 检查描述 + 证据来源 + 判定方式 + 状态
```

金额统一以十进制定点数计算，保留两位；不得使用二进制浮点近似。记录明细数量、明细合计、申请金额和差额。

总体结论：

- 任一确定性规则失败：`不建议通过`。
- 无失败但存在无法判断、读取错误或未知模板：`人工复核`。
- 只有警告、没有失败或无法判断：`可以人工通过（含警告）`。
- 所有适用规则通过：`可以人工通过`。

附件为空、类型不符或解析失败属于读取问题；停止依赖该附件的确定性判断，不自动认定业务失败。

## 6. 输出

默认输出口语化短报告：

1. 第一行说明“可以人工通过”“先别批”或“需要人工复核”。
2. 只列影响结论的 1 至 3 个关键问题。
3. 最后说明没有操作审批，并给出下一步建议。

用户要求详细证据时，再展开：

- 审批实例和当前任务稳定 ID。
- 付款摘要和金额差额。
- 附件的下载信息、下载、类型校验、内容解析四阶段状态。
- 每条规则的期望值、实际值和脱敏证据定位。

无论采用哪种格式，都不得声称已经审批或评论。

## 错误处理

- HTTP 429、连接中断或 5xx：保持输出过滤，只重试一次。
- 401/403、企业不匹配或实例不可读：停止，不换账号或接口绕过。
- 待办列表 `hasMore` 异常：按稳定 ID 去重和目标数量有界停止。
- 下载信息缺少匹配的 `fileId/spaceId` 或签名地址：停止该附件。
- 文件为空、类型不符或解析失败：标记无法判断，保留稳定 ID 和失败阶段。
- 任何只读请求结果不明确时，不执行写操作。

## 安全边界

- 不输出完整银行卡号、身份证号、手机号、Token、Cookie、AppSecret、临时签名 URL或完整请求/响应。
- 银行卡只保留末四位，手机号只保留必要掩码。
- `scripts/credentials.env` 必须为 `600`，不得进入 ZIP。
- 打包必须执行 `scripts/package_skill.sh <output.zip>`，不得自行递归压缩 skill 目录。
- 下载目录只用于当前任务；除非用户明确要求保留，否则核查后清理。
- 本 Skill 严格只读，不提供任何 OA 写命令。
